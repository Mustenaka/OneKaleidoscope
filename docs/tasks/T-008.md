## 目的

`ARCHITECTURE.md` 定了依赖方向和 10 条反模式，但目前它们只是文档里的文字。
**文档里的纪律等于没有纪律** —— M3 一开工，三家 adapter、transport、core 会同时长出来，
靠人眼盯依赖方向必然失守。

本卡把 §2 和 §10 中**可机械判定**的部分变成 CI 门禁，让主管的审核时间花在协议语义上，
而不是数 import。

## 任务 1：`cargo xtask check-deps`

### 规则来源

`docs/dependency-rules.toml` 是唯一真源，形如：

```toml
[crates."kaleido-proto"]
may_depend_on = []                     # 不依赖本项目任何 crate

[crates."kaleido-adapter"]
may_depend_on = ["kaleido-proto"]

[crates."kaleido-adapter-codex"]
may_depend_on = ["kaleido-proto", "kaleido-adapter"]

[crates."kaleido-core"]
may_depend_on = ["kaleido-proto", "kaleido-adapter", "kaleido-transport"]

[crates."kaleido-hostd"]
may_depend_on = ["kaleido-proto", "kaleido-adapter", "kaleido-adapter-*", "kaleido-core", "kaleido-transport"]

[crates."kaleido-cli"]
may_depend_on = ["kaleido-proto", "kaleido-core", "kaleido-transport"]
```

按 `ARCHITECTURE.md §2` / §3 填全。**允许通配（`kaleido-adapter-*`），但只在 hostd 一处需要。**

### 检查内容

读 `cargo metadata`，对 workspace 内部依赖边逐条核对：

1. **越权依赖** —— 声明之外的本项目 crate 依赖，失败
2. **adapter 互相依赖** —— 任意 `kaleido-adapter-A` 依赖 `kaleido-adapter-B`，失败（`ARCHITECTURE.md` A-10）
3. **UI 层直连 adapter** —— `kaleido-cli`、未来的移动端绑定 crate 依赖任何 `kaleido-adapter-*`，失败
4. **`kaleido-proto` 的额外约束** —— 它不许依赖 `tokio`、任何 `*-sdk`、任何 IO crate。
   把禁止列表也放进 `dependency-rules.toml`，别硬编码在 Rust 里
5. **规则覆盖完整性** —— workspace 里存在但 `dependency-rules.toml` 没声明的 crate，**失败**
   （防止新 crate 悄悄绕过守卫）。`spikes/*` 与 `xtask` 显式豁免，豁免名单也写在配置里

### 输出

失败时逐条打印 `<from> -> <to>: 违反了哪条规则`，不要只说「检查失败」。

### 当前状态下的行为

现在 `crates/` 还是空的（M3 才建）。因此：

- `dependency-rules.toml` 先把 §3 的 10 个 crate 全部声明好，**即使它们还不存在**
- `check-deps` 对「声明了但不存在」的 crate **不报错**（M3 会逐个补齐）
- 对「存在但未声明」的 crate **必须报错**

## 任务 2：扩展反模式扫描

在现有 `lint-forbidden` 基础上，把 `ARCHITECTURE.md §10` 中可机械判定的补上：

| 反模式 | 检测方式 |
|---|---|
| **A-1** ANSI 转义解析 | 已有。**补上** `vte`、`ansi-parser`、`strip-ansi-escapes`、`termwiz` 出现在**依赖清单**中即失败（现有实现只扫源码字面量，漏了依赖这一路） |
| **A-2** UI 按 agent 名称分支 | 在 `kaleido-cli` / UI 层的源码中，出现字符串字面量 `"codex"` / `"opencode"` / `"claude"` 且**同一表达式里有比较或 match**，即告警。**这条容易误报**，见下 |
| **A-4** UACP 复用上游判别字符串 | `kaleido-proto` 中出现 `agent_message_chunk`、`tool_call_update`、`item/`、`thread/`、`session/update` 等上游字符串字面量，即失败 |
| **A-6** 手写上游类型 | `kaleido-adapter-*` 中出现 `struct ThreadStartParams` 之类与上游同名的类型定义（对照 `schemas/` 里的 title 列表），即告警 |

### 关于 A-2 的误报处理

按名称分支的模式很难零误报。**要求：宁可误报，不许漏报。**
提供 `#[allow(kaleido::agent_name_branch)]` 式的**显式豁免注释**，
豁免必须写明理由，且**豁免总数打印在 CI 输出里** —— 数量增长本身就是信号。

豁免机制只对 A-2 开放。A-1 / A-4 / A-6 **无豁免**。

## 测试要求

`AGENTS.md §2.3` 适用。每条规则都要有**能失败的**测试：

- `xtask/tests/deps.rs`：构造一份含越权边的假 metadata → 必须失败并指出是哪条边；
  构造合法 metadata → 通过；**存在但未声明的 crate → 必须失败**
- `xtask/tests/antipattern.rs`：每条反模式各一组「命中 / 不命中」样本；
  A-2 的豁免注释生效性；`tests/fixtures/` 与 `schemas/` 目录被排除

**不许用 `#[ignore]`。**
