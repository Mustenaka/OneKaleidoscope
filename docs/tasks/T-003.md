## 目的

`REQUIREMENTS.md` §9 的 **R-4**（上游协议 breaking change 导致 adapter 编译失败）的缓解措施是「类型从官方 schema 自动生成 + CI 每日跑生成与编译检查」。

但在写任何 adapter 之前，必须先做到一件更基础的事：**把三家上游协议的 schema 以确切版本快照进仓库，并能自动检测它们何时变化。**

这份快照同时是主管设计 `PROTOCOL.md` 的原始材料 —— **UACP 的形状必须由三家真实 schema 的交集与并集推导出来，不能凭想象设计。**

## 要求

### 1. 抓取方式（每一份都要可复现）

| 来源 | 抓取方式 |
|---|---|
| **Codex** | `codex app-server generate-json-schema --out schemas/codex` |
| **OpenCode** | 启动 `opencode serve --port <p>`，`GET /doc` 保存为 `schemas/opencode/openapi.json` |
| **ACP** | 已核实，直接按此取：仓库 `agentclientprotocol/agent-client-protocol`，commit `48b2abf1ac750fece26e03e92e773ccbd4754f5d`（tag `v1.3.0` 与 `schema-v1.18.0` 同一提交），文件 `schema/v1/schema.json`、`schema/v1/meta.json`。crate 钉 `agent-client-protocol 1.3.0`。**取完请核对 commit hash 是否与此处一致，不一致要报告** |

**`schemas/VERSIONS.md` 必须记录**：每份 schema 的上游名称、确切版本号（`codex --version`、`opencode --version`、crate 版本 / git tag）、抓取时间、以及**逐字可复制的抓取命令**。

版本号一律钉死确切值，不许写 `latest`。

### 2. `cargo xtask schema refresh`

- 按上表重新抓取全部三份，写入 `schemas/`
- 抓取前检查工具是否存在；缺失时给出**确切的安装命令**，不许静默失败或写出空文件
- 抓取后自动更新 `VERSIONS.md` 中的版本与时间戳

### 3. `cargo xtask schema diff`

- 重新抓取到临时目录，与 `schemas/` 下的快照做**语义化 diff**（解析 JSON 后比较，不是逐行文本比较 —— 键顺序变化不算漂移）
- 无差异：退出码 0
- 有差异：退出码非 0，输出**变化的 JSON 路径清单**（例如 `#/definitions/TurnStartParams/properties/model`），不要打印整份文件
- 上游工具缺失：退出码 2，与「有漂移」区分开

### 4. 漂移监控 CI

`.github/workflows/schema-drift.yml`：每日定时 + 手动触发，跑 `cargo xtask schema diff`，非零即失败。

同 T-002：**仓库暂无远端，本 workflow 不要求实际运行**，只要求是合法 YAML 且与本地命令等价。

## Definition of Done

- [ ] 三份 schema 全部抓取成功并提交，`schemas/VERSIONS.md` 记录完整（含确切版本号与可复制的抓取命令）
- [ ] `cargo xtask schema diff` 在刚抓取后立即运行，返回 0（自洽性检查），粘贴输出
- [ ] 人为改动 `schemas/` 下任一文件的一个字段后再跑 `diff`，**必须非零退出并准确指出变化的 JSON 路径**，粘贴输出；改回原样
- [ ] `xtask/tests/schema_diff.rs` 覆盖：无差异返回 0、字段增删改被检出、**键顺序变化不算漂移**、上游工具缺失返回 2（与漂移区分）
- [ ] ACP schema 的 commit hash 与任务卡所列一致（不一致要报告）
- [ ] `cargo xtask ci` 全绿
- [ ] 交付说明中报告三家的确切版本号

> **本卡不做任何类型生成。** 生成链的可行性验证与工具选型在 [T-005](T-005.md)。
> 若你发现自己在装 typify / progenitor，说明走错卡了。
