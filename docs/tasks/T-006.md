## 主管已裁决的两个遗留问题（照此执行，不用再问）

### 裁决 1：用户名扫描的键/值歧义

你的报告提出：任务卡要求「当前用户名出现即失败」，但 `root` 既可能是用户名也可能是
OpenCode 报文中的合法结构键。

**裁决：你的实现是对的 —— 只扫描 JSON 字符串值，不把同名对象键视为泄漏。**

理由：对象键属于上游报文结构，改键就违反「payload 原样保留」，会让 fixture 失去契约价值。

**补充一条**：键名本身如果是**路径样式字符串**（含 `/` 或 `\` 且指向沙盒外），仍须检出。
把这条规则和理由写进 `README.md` 的替换规则表。

### 裁决 2：`vendor/` 与 `[patch.crates-io]` 的退出条件

离线环境下 vendoring `directories` / `dirs-sys` / `option-ext` 的理由成立，保留。

但 `[patch.crates-io]` 对**整个 workspace 永久生效**，联网后也会继续用 vendored 副本，
这是一个会被遗忘的隐性状态。要求：

- 在 `docs/UPSTREAM.md` 新增一节，记录：vendored 的三个 crate、确切版本、
  引入原因（离线）、**以及移除条件**（「构建环境恢复联网后，删除 `[patch.crates-io]`
  与 `vendor/`，确认 `cargo build --locked` 仍通过」）
- 在 `vendor/README.md` 顶部加一行醒目提示，指向该节

## 任务 4：ACP 超时 —— 最可疑的线索在你自己的 fixture 里

负责人手工跑了 `npx @agentclientprotocol/claude-agent-acp`，输出只有：

```
Need to install the following packages:
@agentclientprotocol/claude-agent-acp@0.63.0
```

**这个结果不能证明任何事。** ACP 适配器是 stdio JSON-RPC server —— 它在等 stdin 上的
`initialize` 请求，没有输入就没有输出。「没打印东西」是正常行为，不是卡住。

而且我们已经知道它能跑：`06-cancel.jsonl` 证明了 `initialize` 与 `session/new` 都成功返回，
**只有 `session/prompt` 之后 120 秒无响应**。

### 主管的假设（请优先验证这一条）

看 `tests/fixtures/acp-claude/06-cancel.jsonl:1`，录制器声明的客户端能力是：

```json
"clientCapabilities":{"fs":{"readTextFile":false,"writeTextFile":false},"terminal":false}
```

**全是 `false`。** 而发出去的 prompt 是「Use a shell tool to run `cargo run -- wait`…」——
让一个被告知「客户端不支持终端、不支持文件读写」的 agent 去跑 shell 命令。

如果 agent 因此走了退化路径或在协商上卡住，就能解释：

- 没有 `tool_call` → 没有 `session/request_permission` → **ACP 那一整列为空**
- `session/prompt` 长时间无下文

### 要求

**把客户端能力改为真实值**：`fs.readTextFile: true`、`fs.writeTextFile: true`、`terminal: true`，
并**实现对应的客户端方法**（`fs/read_text_file`、`fs/write_text_file`、`terminal/*`）。

这不是为了糊弄过去 —— **hostd 本来就必须实现这些**：`REQUIREMENTS.md §2` 端 A 规定
「项目文件树、文件读取、diff 计算由 hostd 直接读盘」，hostd 对 agent 就是 fs 的提供者。
你现在写的这套，就是 hostd 将来要用的那套。

改完后重试 `01`/`02`/`03`。**如果超时依旧**，再按 `AGENTS.md §5` 报告，
并附上改动后的 `initialize` 报文与完整等待期日志。
