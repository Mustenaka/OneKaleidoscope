## 定性：守卫是对的，但它没有留出可通过的路径

两道守卫都在保护真实的风险：

- Codex 那道防止录到一个会碰沙箱外文件的审批请求（`REQUIREMENTS.md §6.3`）
- OpenCode 那道防止 fixture 里出现父级真实项目的路径

**不许通过放宽或关闭守卫来解决。** 正确方向是**让沙箱真的满足守卫的要求**，
以及**让守卫能够正确判定一个确实安全的请求**。

## 任务 1：OpenCode 的隔离项目根，改为自动建立

你在 T-006 的 README 里已经写清了成因与手工解法：

> OpenCode 还会自行向上寻找项目。仅设置 `GIT_CEILING_DIRECTORIES=tests/fixtures` 时，
> 它仍把父级 OneKaleidoscope 识别为项目；成功录制前在 toy project 内临时执行 `git init`，
> 让 OpenCode 的项目根明确停在 sandbox；录完立即删除这个临时 `.git`。

**问题是这一步现在是手工的，负责人跑命令时没有它，守卫就直接拒绝。**

### 要求

把这一步做成录制器的**自动前置**，并保证它是自清理的：

1. 录制 OpenCode 场景前，若沙箱内没有 `.git`，自动 `git init`（不配置 user/远端，只要目录标记）
2. 录制结束后**无条件删除**该临时 `.git` —— 包括失败路径、panic 路径、Ctrl-C 路径
   （用 RAII guard，不要靠 happy path 里的一句 cleanup）
3. **如果沙箱内原本就有 `.git`（不是本次创建的），不要删它**，并在诊断中说明
4. 同时设置 `GIT_CEILING_DIRECTORIES` 指向沙箱父目录，两条措施都要
5. 校验：录制开始前确认 OpenCode 报告的项目根**确实落在沙箱内**；
   落在沙箱外就仍然拒绝（这一条守卫保留）

### 测试

- 自动创建 + 自动删除的往返测试
- **失败路径也删除**：注入一个录制中途失败，断言临时 `.git` 仍被删掉
- 预先存在的 `.git` 不被删除
- 项目根落在沙箱外时仍然拒绝（守卫未被放宽）

## 任务 2：Codex 的「proven safe」守卫，给出可通过的路径

当前错误只说「could not be proven safe」，**没有说是哪一点不满足**。这是首要缺陷：
一个拒绝所有输入且不解释原因的守卫，等于一个死胡同。

### 要求

**第一步：先让它可诊断。** 拒绝时必须输出：

- 守卫检查了哪几项
- 每一项的实际值与期望值
- 具体是哪一项不满足

例如：审批请求里的 `cwd` 实际是什么、规范化后是什么、沙箱的规范化路径是什么、
两者比较的结果；`command` 数组的原始内容、解析出的目标路径、判定结论。

**先把这份诊断跑出来贴给主管**，再决定怎么改。有可能只是路径规范化的问题
（`\\?\` 前缀、`8.3` 短名、大小写、盘符大小写、符号链接），那属于比较逻辑的缺陷，
不是场景设计的缺陷。

**第二步：让场景本身可判定。** `permission-approve` / `permission-deny` 的 prompt
必须让 agent 去动一个**沙箱内的、录制器预先知道确切路径的文件**
（例如沙箱里的 `editable.txt`），而不是给一个开放式指令让模型自选目标。

模型自选目标 → 守卫无法预知期望值 → 永远无法证明安全。
**这是场景设计的问题，不是守卫太严。**

**第三步：审批判据保持严格。** 仍然要求：

- 真实的 server request（`item/commandExecution/requestApproval` 或
  `item/fileChange/requestApproval`）
- 录制器发出真实的批准 / 拒绝响应
- 批准后 agent 确实继续；拒绝后 agent 确实停止
- 目标路径确实落在沙箱内

### 测试

- 目标在沙箱内 → 判定安全，允许录制
- 目标在沙箱外 → 判定不安全，拒绝（守卫未被放宽）
- **路径表示差异不应导致误判**：`\\?\` 前缀、大小写不同的盘符、
  尾部分隔符、`.`/`..` 片段，各一条测试
- 拒绝时的诊断输出包含「检查项 + 实际值 + 期望值」
