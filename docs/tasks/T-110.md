# T-110：R4 自有 Ubuntu 公网远程连接

> 状态：**active**
> 里程碑：R4
> 基线：R3 `main@6799f6d`

## 1. 用户可见目标

用户离开家庭局域网后，Android 通过蜂窝网络继续连接 PC 上的 `kaleido-hostd`：优先公网
P2P，失败后自动切到自有 Ubuntu relay。切换路径、App 后台/冷启和 PC 短暂离线都不得造成
projection、队列或 Attention 丢失、重复或回退；手机必须诚实显示 `PeerToPeer`、`Relayed`
或 `Offline`。

Ubuntu 服务只做 rendezvous、路由、密文字节转发和无敏感内容的 push 唤醒。它没有业务
内容密钥，不持有 provider 凭据，也不能读取消息、代码、diff、工具参数或完整路径。

## 2. 开工前必须固定的合同

先完成只读审计并写一份生效 ADR，至少决定：

1. Host、Device、Ubuntu 服务三方身份与持久密钥；密钥轮换、吊销和恢复边界；
2. rendezvous 注册、presence TTL、route ID、重放保护、限额与错误粒度；
3. 公网 P2P 与 relay 如何提供双向 byte pipe；路径选择、降级和恢复状态机；
4. PC ↔ Android 的端到端加密边界。优先复用 R3 的 Host SPKI pin、TLS 1.3 和设备认证作为
   内层端到端会话，让 relay 只看到 opaque TLS records；若不采用，ADR 必须说明原因和
   等价的认证、前向保密、nonce/sequence/rekey/replay 方案；
5. push token 注册、吊销、过期和 payload 白名单。R4 必须实接 Android FCM；接口不得把
   Android 写死进共享协议，APNs 实机验收留在 R8；
6. LAN → P2P → relay、网络切换、session expiry、PC offline 与 projection cursor resume
   的精确顺序；
7. Ubuntu 部署、私钥权限、速率/连接/带宽上限、健康检查、滚动升级和安全日志字段；
8. D-B2 活进程树终止与 D-B8 脱敏标签在 R4 的结清方式。

新增公网 wire 形状不得私设。必须选择并记录以下一种版本边界：独立且闭合的 remote-control
协议版本，或提升 `TRANSPORT` pre-1.0 minor；随后在同一提交中同步 ADR、合同、Rust 类型、
双端消费面和错误路径测试。UACP 业务语义没有变化时不得为远程路由无故改动 UACP。

`spikes/kaleido-spike-iroh` 与冻结的 T-001 只能作为历史测量证据。若采用 iroh 或其他网络库，
必须对照当时的官方稳定文档重新验证 API、自托管能力、Android 支持和安全边界，不能把公共
测试 relay 直接当生产 Ubuntu 服务。

## 3. 交付面

### 3.1 公网 transport 与 relay

- 新增独立 `kaleido-relay` crate 及 Ubuntu 服务入口；同步 workspace member 和
  `docs/dependency-rules.toml`；
- hostd 与 mobile 均可向 rendezvous/relay 建立受认证的出站连接，不要求家庭路由器开放端口；
- P2P 成功时走直连；连接失败、超时或网络切换时自动 relay；恢复直连不得造成业务重放；
- relay 只转发有界密文字节流，实施 per-route/per-device/global 连接、帧、带宽和 idle 限额；
- relay 无法构造或解析 UACP business frame，日志中没有正文、ContentRef、完整 endpoint 或
  用户路径。

### 3.2 hostd、Rust core 与 Android

- `kaleido-hostd` 维护 remote presence、path selection 与 reconnect，正确发布
  `HostReachability::PeerToPeer` / `Relayed` / `Offline`；
- `kaleido-core` 在 LAN/P2P/relay 之间切换时继续使用每个 `ProjectionKey` 的 last-good
  cursor；不能重置缓存或把 `CurrentFollows` 当作无条件成功；
- Android 注册 FCM token，后台或进程被回收时由无敏感 push 唤醒并恢复订阅；
- durable revoke 必须同时阻止 LAN、P2P、relay 和后续 push；已进入 canonical durable
  write path 的命令不回滚，未提交请求不得在吊销后进入 Broker；
- PC/runtime 真正离线时手机进入带时间信息的离线状态，Ubuntu 不得替代 Agent 执行。

### 3.3 进程与隐私收口

- Windows、macOS、Linux 的 Codex runtime 终止必须覆盖仍存活的真实子进程树；只结束根 PID
  不算通过；
- push、relay、rendezvous、普通 tracing 和错误报告使用字段白名单；
- D-B8 的 `<HOME>` / `<SANDBOX>` 标签必须在不泄漏用户名或完整路径的前提下保持诊断含义；
- 服务私钥和 device/host credential 使用 owner-only 权限、原子写入、fsync 和损坏 fail-loud。

## 4. Definition of Done

### 4.1 合同和自动化

- [ ] 生效 ADR 与实际 wire/状态机一致；未知版本、kind、字段、route 和 response ID fail-closed；
- [ ] relay 对密文采样只得到随机化记录；同一明文重复发送不能由 relay 识别为相同 payload；
- [ ] wrong host/device/service identity、tamper、replay、out-of-order、expired registration、
      revoked device 和越限连接均有拒绝路径；
- [ ] P2P 失败自动 relay，relay 中断后从 last-good cursor 恢复，无漏、无重、无 cursor 回退；
- [ ] LAN/P2P/relay 切换只在真实路径建立后更新 reachability，不把 connecting 写成 online；
- [ ] FCM payload 只含有界 opaque wake/route 标识；日志和 push canary 扫描不含业务明文、
      ContentRef 正文、token、完整 endpoint/path 或用户名；
- [ ] durable revoke 先 fsync 再断链，并在重启后继续拒绝所有远程路径和 push；
- [ ] Windows、macOS、Linux CI 各自运行“根进程 + 存活子进程”终止测试并证明两者都退出；
- [ ] 至少六处安全/恢复变异实际变红并恢复，至少覆盖：relay 解密边界、身份绑定、重放、
      path fallback、cursor resume、process-tree termination；
- [ ] `cargo xtask ci`、三平台 CI、Android CI 与 Ubuntu relay 集成测试全绿。

### 4.2 真实端到端门禁

在自有 Ubuntu 实例、家宽 PC 和实体 arm64 Android 上完成：

1. Android 关闭 Wi-Fi，仅通过蜂窝网络连接；不得使用 `adb reverse`、VPN 同网段或模拟 projection；
2. PC/手机通过 rendezvous 建立公网路径，记录最终是 `PeerToPeer` 或 `Relayed`；
3. 强制 P2P 失败，客户端在有界时间内自动进入 `Relayed`，真实 Codex 的七类 R3 projection
   继续可见；
4. 手机提交 prompt 或排队输入，并处理一次真实结构化 Attention；
5. App 进入后台并由真实 FCM 唤醒；随后执行蜂窝/Wi-Fi 切换和进程冷启，cursor 精确恢复；
6. 暂停 hostd 后手机显示 Offline；恢复后不丢、不重放命令；
7. 吊销设备后 LAN/P2P/relay 均无法重新认证；
8. 从 Ubuntu relay 的日志、抓包和进程内诊断中扫描业务 canary，结果必须为零命中。

真实证据写入 `docs/gates/T-110-evidence.md`：记录 commit、Ubuntu/Android/PC 版本、网络拓扑、
路径状态、cursor、阶段耗时和安全扫描结果，但不得记录公网凭据、完整 endpoint、push token、
DeviceId、正文或用户路径。NAT 20 轮只作为性能/容量数据，不是是否实现 relay 的门禁。

## 5. 文件边界

允许修改：

- 新 ADR、`docs/TRANSPORT.md`、必要时 `docs/PROTOCOL.md`、架构/状态/里程碑/任务和 evidence；
- workspace manifests、`docs/dependency-rules.toml`、新 `crates/kaleido-relay/**`；
- `crates/kaleido-transport/**`、`kaleido-hostd/**`、`kaleido-core/**`；
- Android platform/data/lifecycle 与对应测试、R4 部署/门禁脚本和 CI；
- 仅为 D-B2 修改 `kaleido-adapter-codex/src/platform/**`、`process.rs` 及精确测试。

禁止修改：

- `schemas/**`、历史 fixture、provider decoder/reducer 语义；
- OpenCode/Claude adapter、跨 Agent workflow、iOS 产品 UI、编辑器/Git 功能；
- PTY/TUI/ANSI/屏幕/OCR/transcript 轮询；
- 让 Ubuntu 持有 provider 凭据、项目文件、业务内容密钥或可解密正文；
- 用第三方公共 relay 冒充自有 Ubuntu 交付，或用 LAN/`adb reverse` 冒充蜂窝公网门禁。

需要付费服务、真实 FCM/APNs 凭据、DNS/防火墙变更或生产 Ubuntu 部署时，先完成所有不依赖
外部权限的实现与测试，再明确列出最小人工操作；不得用 mock 结果替代真实门禁。
