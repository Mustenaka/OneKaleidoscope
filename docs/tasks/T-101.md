# T-101: UniFFI 可表达性编译探针

> 状态：**已作废，不得下发。**
> 绑定生成与 Kotlin 编译已在一次性 R1 恢复中完成；剩余的 Swift 编译（UB-R1-S）
> 与新发现的 UniFFI 调用面缺口（G-R1-1）由 **[T-102](T-102.md)** 承接。
> 本文件仅作历史保留。

## 这张卡决定什么

[MILESTONES](../MILESTONES.md) R1 门禁要求「移动端绑定对最小真实类型编译通过」。
主管在 R1 中只做了**人工**可表达性审计（[PROTOCOL.md](../PROTOCOL.md) §2 R-P1 + R1 评审 §4），
没有跑过真实的 bindgen。因此该门禁项目前记为**未取得机器证据**。

本卡的唯一目的是把它变成机器证据，或者证明 R-P1 的规则不足并让主管修协议。

## 前置合同

- [PROTOCOL.md](../PROTOCOL.md) §2 R-P1（允许的构造清单）、§1（枚举内部标签 `kind`）
- `crates/kaleido-proto` 全部公开类型
- [ARCHITECTURE.md](../ARCHITECTURE.md) §9（UniFFI 只出现在 `kaleido-core`，不进 proto）

## 用户可见结果

`cargo xtask`（或任务卡商定的命令）能在本机生成 Kotlin 与 Swift 绑定源码，
并且生成过程对以下类型不报"不支持"：

`Session`、`SessionStatus`、`LiveBinding`、`Turn`、`Item`、`ItemBody`、`ItemStatus`、
`QueueEntry`、`QueueState`、`AttentionItem`、`AttentionSubject`、`JoinState`、
`RuntimeCapabilities`、`CapabilityState`、`ContentRef`、`CanonicalError`、
`Cursor`、`StateEffect`、`ProjectionEnvelope`。

## 产出

- `crates/kaleido-core`：最小 crate，只依赖 `kaleido-proto` 与 `uniffi`；
  导出上述类型和一个平凡函数（例如返回 `PROTOCOL_VERSION`），不含业务逻辑；
- 绑定生成步骤与命令写进 `docs/DEVELOPMENT.md`；
- `docs/gates/T-101-evidence.md`：工具精确版本、命令、原始输出。

## Definition of Done

- [ ] Kotlin 绑定生成成功，输出无 unsupported/skipped 警告；
- [ ] Swift 绑定生成成功，同上；
- [ ] 生成产物不提交进仓库（写进 `.gitignore`）；
- [ ] 一条错误路径：临时给 `kaleido-core` 加一个含元组或 `serde_json::Value` 的
      导出类型，证明生成器**确实拒绝**；随后删除该类型。这条是本卡的核心证据，
      因为它证明门禁真的有约束力；
- [ ] `cargo xtask check-deps` 通过（`kaleido-core` 的规则条目已存在）；
- [ ] fmt / clippy / 相关测试绿。

## 允许的结论包括「R-P1 不够」

如果生成器拒绝了某个当前 proto 里已有的类型，**这是一个合格的交付**：
停下来按 `AGENTS.md` §5 报告，列出被拒类型、生成器原始错误和最小复现，
由主管决定修改 [PROTOCOL.md](../PROTOCOL.md) §2 还是修改该类型。
**不许**为了让生成器通过而自行改动 `crates/kaleido-proto`。

## 边界

- 禁止修改 `crates/kaleido-proto/**`、`docs/PROTOCOL.md`、`docs/adr/**`；
- 禁止把 `uniffi` 加进 `kaleido-proto`；
- 不写 Android / iOS 应用代码，不建 Gradle / Xcode 工程；
- 不实现任何业务逻辑、传输或 provider 接入。
