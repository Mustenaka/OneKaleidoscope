# T-113：R5 多 Provider Broker、移动端与最终门禁

> 状态：**active，Claude 实体 Android 子格已通过；受 T-111 OpenCode 上游漂移与最终总门禁阻塞**
> 里程碑：R5
> 集成基线：`origin/main@b54a12638cd044b277747d5fbc22627ad2adb016`

## 1. 用户可见目标

把 Codex、OpenCode、Claude 三家的 Broker 管理会话同时接入同一个 `kaleido-hostd`、durable
store、projection journal、`kaleido-core` 与 Android App。用户只按 runtime capability 看到可执行
动作，可以发现/打开会话、查看历史与实时 turn、处理 Attention、发送 prompt/queue/interrupt，
并在 provider 或网络中断后从 last-good projection cursor 恢复。

## 2. 集成要求

- provider-neutral runtime registry/discovery，hostd 不再是 Codex-only composition root；
- Project 可含三家 binding；Session ownership/history/live/capability 证据保持独立；
- device command 继续走可信 ingress/outbox；runtime 只处理自己的 Session，跨 scope/raw ID/Attention
  reply 必须拒绝；
- Android 不新增 provider 协议或 provider-name feature branch，只复用八类 projection 和 command；
- R4 未合并或公网门禁未通过时，不得把 LAN 实测称为公网恢复。R4 合并后必须在最终 SHA 重跑。

## 3. Definition of Done

- [ ] 同一 hostd 同时发现三家 runtime/session，并在 ProjectIndex/SessionIndex/Transcript/
      LiveActivity/InputQueue/AttentionInbox/RuntimeCapability 上无 provider 专属 UI；
- [ ] 三家各有真实 streaming/history/waiting-human/reconnect 证据；缺失能力在 Android 可见；
- [ ] 不支持 steer 时 queue 保持 Pending；只有当前 turn 的结构化注入确认才变为 steer；
- [ ] hostd/provider crash、移动断线、App 冷启与 provider resume 后 cursor 无漏、无重、无回退；
- [x] `cargo xtask ci`、Windows/macOS/Linux CI、Android CI 全绿，并链接 exact commit runs；
- [ ] 实体 arm64 Android + 真实 Wi-Fi（R4 合并后再加蜂窝/relay）完成三家会话纵切，禁止
      `adb reverse`、模拟 projection 或 mock runtime；
- [ ] 至少覆盖 capability、runtime route、Attention scope、queue/steer、reconnect、cursor resume
      六处变异，实际变红并恢复；
