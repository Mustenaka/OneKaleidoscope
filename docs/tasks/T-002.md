## 要求

### 1. Workspace 配置

- `[workspace.package]`：统一 `edition`、`rust-version`、`license`、`repository`
- `[workspace.dependencies]`：**只放确定会被多个 crate 共用的基础依赖**（`tokio`、`serde`、`serde_json`、`thiserror`、`tracing`、`tracing-subscriber`）。不要预置 `iroh`、`agent-client-protocol` 等 —— 那些属于后续架构任务
- `[workspace.lints.rust]` / `[workspace.lints.clippy]`：见下

### 2. Lint 强制（这是本任务的核心价值）

在 `[workspace.lints.clippy]` 中至少设置：

```toml
unwrap_used = "deny"
expect_used = "deny"
panic = "deny"
indexing_slicing = "deny"
todo = "deny"
unimplemented = "deny"
dbg_macro = "deny"
```

`[workspace.lints.rust]`：

```toml
unsafe_code = "deny"          # FFI 边界的 crate 单独 allow 并写安全性论证
missing_debug_implementations = "warn"
```

**测试代码的豁免方式必须是「窄口径」**：只允许在 `#[cfg(test)]` 模块或 `tests/` 目录内用 `#![allow(clippy::unwrap_used, clippy::expect_used)]`，不许在 crate 根部整体 allow。在 `docs/DEVELOPMENT.md` 里写清这条约定。

**验证方式（DoD 会查）**：在 `xtask` 里故意写一行 `let _ = Option::<u8>::None.unwrap();`，确认 `cargo clippy --all-targets -- -D warnings` 会红；确认后删掉，并在交付说明里贴出那次失败的输出。

### 3. `cargo xtask` 命令

不引入 `just` / `make` / shell 脚本 —— 用 Rust 写，三平台行为一致。

| 命令 | 行为 |
|---|---|
| `cargo xtask ci` | 依次跑 fmt-check、clippy、test、lint-forbidden；任一失败即非零退出，并明确指出是哪一步 |
| `cargo xtask lint-forbidden` | 扫描仓库，命中禁用模式即失败，输出 `文件:行号: 命中的模式` |

### 4. `lint-forbidden` 的禁用模式

扫描范围：`crates/`、`spikes/`、`xtask/` 下的 `*.rs`（**排除** `tests/fixtures/`、`schemas/`、`target/`）。

| 模式 | 依据 |
|---|---|
| `todo!` / `unimplemented!` | AGENTS.md §2.4 |
| `// TODO` / `// FIXME` | AGENTS.md §2.4 |
| `#[ignore]` | AGENTS.md §2.3（禁止用 ignore 绕过测试） |
| `\x1b[` / `\u{1b}[` 字面量、`strip_ansi`、`vte`、`ansi_parser` | AGENTS.md §2.2 / OBJ-2，禁止 ANSI 转义解析 |

**没有豁免机制** —— 这些模式一条都不该出现在声称完成的代码里。如果你认为某处必须豁免，按 `AGENTS.md §5` 报告，不要自己加 allow-list。

`xtask/tests/forbidden.rs` 必须验证：给一个含 `todo!()` 的临时文件会被命中；给一个干净文件不会被命中；`tests/fixtures/` 下的文件即使含 ANSI 字节也**不**被命中。

### 5. CI

`.github/workflows/ci.yml`：

- matrix：`windows-latest`、`macos-latest`、`ubuntu-latest`
- 步骤：checkout → 装 toolchain（读 `rust-toolchain.toml`）→ 缓存 → `cargo xtask ci`
- **Windows 是首要平台**：矩阵里 Windows 放第一位，且不允许 `continue-on-error`

> **本仓库目前没有远端**，CI 无法实际运行。因此 DoD 只要求：workflow 为合法 YAML、步骤与本地 `cargo xtask ci` 等价、**在 Windows 上本地跑通 `cargo xtask ci`**。macOS/Linux 的实际验证推迟到仓库上云后（会在 G8 补验）。
