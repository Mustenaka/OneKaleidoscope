## 问题陈述

负责人在自己的 PowerShell 里执行：

```
cargo run -p xtask -- schema diff
xtask: tool `opencode` has version `1.18.9`, expected `1.18.8`;
       install exactly with: npm.cmd install --global opencode-ai@1.18.8
error: process didn't exit successfully (exit code: 2)
```

**一个漂移检测器，因为「装的版本与快照不一致」而拒绝运行。**
而「版本不一致」正是它唯一需要检测的东西。

这不是你的实现错误 —— T-003 的任务卡把「工具缺失」与「版本不符」归进了同一个失败类别，
是主管的设计缺陷。ADR-0008 已改正模型。

同时这已经是版本问题第三次挡住我们自己（T-006 的 2380 处漂移、T-010 的沙箱内 `.CMD`、本次）。
负责人明确要求**一次性解决，并考虑三家频繁更新下的前向兼容**。

## 任务 1：`schema diff` 永不因版本不符而拒绝运行（ADR-0008 D-2/D-4）

### 行为

- 始终对**实际安装的版本**执行比较
- 输出同时报告 snapshot version 与 observed version
- 版本不符只是输出中的一行提示，**不是失败**

### 退出码（严格按此实现）

| 码 | 条件 |
|---|---|
| `0` | 面内无漂移。**含「版本不同但面内一致」**，此时打印醒目提示 |
| `1` | **面内**有漂移，输出变化的 JSON 路径清单 |
| `2` | 工具不存在或无法执行。**版本不符不属于此类** |

### 测试

- 版本不符 + 面内一致 → 退出 `0`，输出含两个版本号与提示
- 版本不符 + 面内漂移 → 退出 `1`
- 工具确实不存在 → 退出 `2`
- **把这条修复改坏（恢复成「版本不符即退出 2」），第一条测试必须变红**

## 任务 2：必需面分区（ADR-0008 D-3，本卡核心）

### `schemas/required-surface.toml`

声明式列出 UACP 依赖的上游条目。**本卡建立 provisional 版本**，定稿由主管随 `PROTOCOL.md` 产出。

Provisional 内容按现有已知证据填写，至少覆盖：

**Codex**
- 生命周期：`initialize` / `initialized` / `thread/start` / `thread/started` /
  `thread/resume` / `thread/list` / `turn/start` / `turn/started` / `turn/completed` /
  `turn/interrupt` / `thread/status/changed`
- Item：`item/started` / `item/completed` / `item/agentMessage/delta` /
  `item/reasoning/textDelta` / `item/commandExecution/outputDelta` / `item/plan/delta`
- 审批（服务端请求）：`item/commandExecution/requestApproval` /
  `item/fileChange/requestApproval` / `item/permissions/requestApproval` /
  legacy `execCommandApproval` / `applyPatchApproval`
- Elicitation：`mcpServer/elicitation/request`
- 类型：上述方法的 Params/Response，以及 JSON-RPC 信封、`ServerRequest`、`ReviewDecision`

**ACP v1**
- `initialize` / `session/new` / `session/load` / `session/list` / `session/prompt` /
  `session/cancel` / `session/request_permission`
- 客户端方法：`fs/read_text_file` / `fs/write_text_file` / `terminal/*`
- 类型：`SessionUpdate` 的 11 个变体、`PermissionOption` / `PermissionOptionKind` /
  `RequestPermissionOutcome`、`agentCapabilities`

**OpenCode**
- `GET /session` / `GET /session/:id` / `GET /session/:id/message` /
  `POST /session/:id/message` / `POST /session/:id/abort` /
  `POST /session/:id/permissions/:permissionID` / `GET /event` / `GET /project/current`
- 类型：`Session` / `Message` / `Part` / 权限与 question 相关 schema

**每一条都要写明「为什么需要它」**（对应哪个 UACP 事件变体或方法族）。
没有理由的条目一律删掉 —— 那说明它不在必需面。

> **防滥用（ADR-0005 D-4 / ADR-0008 D-3）**：必需面由 `PROTOCOL.md` 的需要推导。
> **发现某条漂移了就把它移出必需面 = 用上游变更裁剪协议 = 打回。**

### 分区报告

```
schema diff: observed codex 0.146.0 (snapshot 0.146.0), opencode 1.18.9 (snapshot 1.18.8)
  in-surface   : 0 drift
  out-of-surface: 2380 drift (548 added / 1598 changed / 234 removed)
  -> exit 0 (out-of-surface drift is informational)
```

面内有漂移时列出确切 JSON 路径与所属必需面条目。

### 测试

- 面外漂移 → 退出 `0`，报告数量
- 面内漂移 → 退出 `1`，列出路径与所属条目
- 必需面条目缺少「为什么需要」字段 → 配置解析失败（fail-closed）
- 必需面引用了 schema 里不存在的条目 → **失败并指出**（防止必需面自己写错）

## 任务 3：纵向漂移记录（ADR-0008 D-6）

`schemas/surface-history.jsonl`，每观测到一个新版本追加一行：

```json
{"observed_at":"2026-07-30T...","tool":"opencode","version":"1.18.9","surface_digests":{"GET /event":"sha256:...","Session":"sha256:..."}}
```

- 同一 tool+version 已存在则不重复追加
- 完整快照仍只保留当前 snapshot version（不要为每个版本存 275 个文件）
- 提供 `cargo xtask schema history` 打印某个必需面条目跨版本的变更时间线

## 任务 4：supported range 是声明而非门闩（ADR-0008 D-7）

`docs/UPSTREAM.md` 增加一节，每个工具记录：

| 字段 | 说明 |
|---|---|
| snapshot version | 当前完整快照来自哪个版本 |
| supported range | 已实测可配合工作的范围 |
| 判定依据 | 哪次实测、什么结论 |

超出 range 时：**正常运行**，打印「未验证的版本」提示。**不许拒绝执行。**

## 任务 5：禁止按版本号分支功能（ADR-0008 D-5）

把这条纪律机器化，接到 T-008 的反模式扫描里，作为新反模式 **A-11**：

> 源码中出现「版本号字符串或数字与常量比较后据此开关功能」的模式即失败。

判定方式：识别对版本类型/变量的比较运算（`>=` / `<` / `==` 等）**且**其结果用于控制流。
**与 A-2 一样允许带理由的显式豁免，豁免总数打印在 CI 输出里；A-1/A-4/A-6 仍无豁免。**

纯粹的**记录与展示**用途不算违规（例如把 observed version 打进诊断输出）。
测试代码不算违规。

### 测试

- `if version >= "1.18.9" { enable_x() }` → 命中
- `println!("observed {version}")` → 不命中
- 带理由豁免注释 → 不命中，且豁免计数 +1
