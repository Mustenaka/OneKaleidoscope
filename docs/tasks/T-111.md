# T-111：R5 OpenCode 真实结构化会话与 D-B11

> 状态：**active；实现与部分真实 OpenCode 证据已落地，最终门禁未闭合**
> 里程碑：R5
> 基线：`origin/main@893e930`

## 1. 用户可见目标

`kaleido-hostd` 通过 OpenCode 公开的 server REST + SSE 连接共享或 Broker 管理的 runtime，
在现有 canonical state 与八类移动端投影上提供会话发现、历史、实时 turn、审批、结构化问题、
prompt、interrupt、队列与断线恢复。不能创建 OpenCode 专属 UI，也不能把 REST 历史轮询称为实时。

本卡先结清 D-B11。开卡时提交快照与支持基线是 `1.18.8`，本机真实 fixture 为
`1.18.11`，2026-08-10 npm current 为 `1.18.16`。支持范围只由逐项 schema 审查和对应版本
真实 runtime/fixture 证据扩展，不能因“面内暂时无漂移”自动扩展。

## 2. 上游与解码合同

- 原样 `/doc` OpenAPI 3.1 快照只通过 `cargo xtask schema refresh` 更新，禁止手工修改；
- 当前纵切所需 operation/type 子集由 `PROTOCOL.md` 的 Session/Turn/Item/Attention/Command/
  Capability 语义推导；
- OpenAPI 3.1 → 规范化层 → Rust 生成器。每条实际命中的规范化规则必须有名字、命中数、
  before/after 单测并登记进 `docs/UPSTREAM.md`；不得删除字段、放宽约束或猜语义；
- 生成的上游类型只存在于 `kaleido-adapter-opencode`，不穿透到 canonical/mobile；
- provider 映射同步生效 ADR、`PROTOCOL.md` 映射附录、required surface 与真实 fixture。

决策见 [ADR-0026](../adr/0026-opencode-generated-rest-sse.md)。

## 3. 交付

1. `kaleido-adapter-opencode`：server REST、runtime 探测、session list/get/messages、SSE live
   subscription、prompt、abort、permission reply、question reply；raw ID 只进 adapter 私有绑定表；
2. reducer：把真实 message/part/event 映射为现有 Project/Session/Turn/Item/Attention；未知标签产生
   diagnostic 或 protocol violation，不 panic、不猜成 AgentMessage；
3. 能力：仅由当前连接实际成功的 endpoint、SSE 流量和 runtime acceptance 证明；queue 不冒充 steer；
4. 恢复：SSE 中断后按 REST snapshot + 新 SSE tail 收敛；因为上游无 cursor，必须标记
   `lossless_replay = false`；重复 event 不重复 canonical effect，scope/身份冲突 fail-closed；
5. 真实证据：隔离 toy project 中用精确版本录制 discovery、streaming turn、permission、question、
   abort 和 reconnect 中实际可触发的场景。触发不到的能力保留 `NotVerified`/`Unsupported` 并记录尝试。

## 5. 边界

允许修改 OpenCode schema/required surface/UPSTREAM、provider-neutral adapter 的必要扩展、
`kaleido-adapter-opencode`、按需真实 OpenCode fixture、协议映射 ADR/附录和精确测试。
禁止 PTY/TUI/ANSI/OCR/屏幕、transcript 轮询冒充实时、手写上游类型、mock 冒充 runtime 验收、
按 provider 名称提升能力或修改历史 fixture 使其迎合实现。
