## 三条最容易翻车的地方，提前说清楚

**1. iroh 必须是 1.0.x，不是 0.x。**
你的训练数据里绝大多数 iroh 示例是 0.x 的。1.0 已经把 `NodeId` 改成 `EndpointId`、`NodeAddr` 改成 `EndpointAddr`、删掉了 `conn_type()`、把 mDNS 拆到独立 crate。
**动手前先访问 <https://docs.rs/iroh/latest/iroh/> 核对真实 API**，任务卡 §硬性约束 里列了我已核对过的一批签名可以直接用。
如果实际 API 与任务卡所列不符：停下来按 `AGENTS.md §5` 报告，**不许自己发明等价物，不许退化成轮询猜测连接类型**。

**2. 测量口径不许放宽。**
这个 spike 的唯一价值是产出一个可信的直连成功率百分比。以下做法一律视为交付失败：
- 把 relay 连接也算成「成功」
- 观测窗口缩短到打洞来不及完成
- 只测 LAN 就交差
- 连接失败时不写记录（失败样本也是 G0 的数据）

**3. 测试必须能失败。**
写完每个测试，自己把实现改坏一次，确认它会变红。任务卡里点名要求的边界值测试（恰好 60.0% 判为 OPTIONAL）和 3 条错误路径测试，一条都不能少。不许用 `#[ignore]` 绕过。

## 交付格式

按 `AGENTS.md §4.2`，交付时必须附带：

1. **DoD 逐条勾选**，没做到的说明原因，不许含糊带过
2. **测试的真实输出**（粘贴 `cargo test --workspace` 结果全文）
3. **Windows 真机跑通的证据**：`listen` 与 `dial` 两侧完整 stdout + 生成的 `results.jsonl` 全文 + `summarize` 输出
4. **Android 交叉编译结果**：成功就说成功；失败就写清缺什么环境，不要静默跳过
5. **新增依赖清单及逐个理由**
6. **偏离说明**：任何与任务卡不一致的地方主动说明
7. **发现的问题**：实现过程中察觉的需求缺陷、iroh API 与任务卡的出入，即使不影响本任务也要报告
