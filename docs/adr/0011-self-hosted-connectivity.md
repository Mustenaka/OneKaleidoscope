# ADR-0011: 自有 Ubuntu 协调与 relay 是 v1 组件

- 状态：**已接受，2026-07-30**
- 决策人：项目负责人
- 修订：ADR-0001 中“由 G0 直连率决定 relay 是否必做”的部分

## 背景

项目负责人已有一台 Ubuntu 服务器，可用于 P2P 打洞验证、协调和中继。真实移动网络存在 CGNAT、
对称 NAT、网络切换和手机后台回收。即使平均直连率良好，也不能把可靠远程控制建立在“多数情况下能打洞”
之上。

## 决策

### D-1 连接分三层

1. 局域网直连；
2. 公网 P2P 直连；
3. 自有 Ubuntu relay 回退。

客户端自动选择并显示当前路径。relay 从 v1 开始设计和测试，不由直连率阈值决定是否存在。

### D-2 服务器职责受限

服务器只负责：

- 配对和设备目录；
- rendezvous/discovery；
- 密文字节流 relay；
- push 唤醒；
- 有界、可过期的加密离线信封（若实现）。

它不持有 provider 凭据、不执行 Agent、不读取项目、对话、diff 或工具参数。

### D-3 端到端加密

业务内容在 PC 和手机端加解密。服务器被完全攻陷时，攻击者仍不能读取历史或命令正文。
推送只携带无敏感内容的路由/唤醒标识。

### D-4 G0 重新定位

原 20 轮 NAT 测试保留为性能、地域和 relay 容量依据，不再是协议、Broker 或移动端开工门禁，
也不再决定 relay 是否属于 v1。

## 后果

- 可以尽早做 LAN 产品纵切，同时并行准备远程可靠性；
- Ubuntu 部署、监控、密钥轮换和 relay 容量进入发布门禁；
- PC 离线时手机只能显示离线，服务器不能“代跑”任务。
